## Introduction to SQL

**SQL**: Structured Query Language, 结构化查询语言

SQL 包含几个部分:

- **DDL** (Data-definition Language) **数据定义**
  - Create table, alter table, drop table
  - create index, drop index
  - create view, drop view
  - create trigger, drop trigger
- **DML** (Data-manipulation Language) **数据操纵**
  - select...from
  - insert, delete, update
- **DCL** (Data-control Language) **数据控制**
  - grant, revoke

---

## 1. Data Definition Language (DDL)

DDL 的主要功能:

- 定义每个关系的**关系模式(schema)**
- 指定每个属性的**域值(domain)**
- **完整性约束**
- 定义每个关系在磁盘上的**物理存储结构**
- 定义每个关系维护的**索引(indices)**
- 定义对关系的**视图(view)**

### 1.1 Domain Types in SQL

- `char(n)` : 固定长度字符字符串, 用户指定长度为n
- `varchar(n)`: 可变长度的字符字符串, 用户指定最大长度为n
- `int`: 整数,(机器依赖的整数有限子集)
- `smallint`: 小整数(整数域的一个机器依赖的子集)
- `numeric(p,d)`: 定点数, 用户指定**精度为p位数字**, 其中小数点后有d位
- `real, double precision`: 浮点数和双精度浮点数, 其精度取决于机器
- `float(n)`: 浮点数, 用户指定至少n位有效数字的精度
- 所有域类型都允许`null`值; 将某个属性**声明为`not null`**可以禁止该属性取null值
- `date`: 日期类型, 包含四位数的年份, 月份和日期
  - 例如: `date '2007-2-27'`
- `time`: 表示一天中的时间, 包括小时, 分钟和秒
  - 例如: `time '08:15:30'`
- `timestamp`: 日期 + 时间 的组合, 即完整的时间戳
  - 例如: `timestamp '2007-2-27 08:15:30.75'`

> 在 SQL Server 2000 中, 日期和时间的类型统称为"datetime"

SQL 中有许多函数, 用于**处理各种数据类型** 以及 **类型转化**

### 1.3 Drop and Alter Table 删除 和 修改 表

**Drop Table**:

`DROP TABLE` 会从数据库中删除关于被删除关系的所有信息

- `DROP TABLE r;`

**Alter Table**:

1. 修改表用于向已经存在的关系中**添加(add)**:

- `ALTER TABLE r 	ADD A D;`
- `ALTER TABLE r ADD (A1 D1,..., An Dn);`

​	其中 A 是属性名字, D是A的域

- 所有元组的新的属性的值都会被赋值为`null`

2. 修改表也可以**删除(drop)**关系的一些属性:

- `ALTER TABLE r DROP A`

> 但是很多数据库不支持对属性的删除

3. 修改表也可以**修改(modify)**关系的属性:

- `ALTER TABLE instructor MODIFY (ID char(10), salary not null)`

## 2. Basic Structure of Select

一个典型的 SQL 查询为如下形式

```sql
SELECT A1, A2, ... An
FROM r1, r2, ..., rm
WHERE P
```

其对应的关系代数为: $\Pi _{A_1, A_2, ..., A_n}(\sigma _P(r_1 \times ... \times r_m))$

这个 SQL 查询的结果是一个关系

---

### 2.1 The select Clause (select子句)

`select`子句对应着 关系代数中的 **投影$\Pi$**

**note**: SQL 中不允许字符`-`出现在名字中;

​	例如: 使用`dept_name`; 而不是`dept-name`

**note**: SQL 名称**不区分大小写**

SQL **允许**关系中以及查询结果中**存在重复项**;

- 若要强制消除重复项, 可以在`SELECT`后添加关键字`distinct`

- 相反的关键字`all`允许保留重复项

> 默认情况下, 允许重复项, 即**ALL是默认选项**

SELECT 子句中, `*`代表**所有属性**;

- `SELECT * FROM instructor;`

SELECT 子句可以包含算数表达式, 涉及运算符`+,-,*,/`, 并作用于常量 或者 元组的性质上(**广义投影**)

​	例如:`SELECT ID, name, salary * 1.05 FROM instructor;`

---

### 2.2 The Where Clause (where子句)

**`WHERE`**子句 用于指定结果必须**满足的条件**, 它对应于关系代数中的**选择谓词 selection predicate $\sigma$**

`WHERE` 子句中, 比较结果可以用**逻辑连接词** `AND OR NOT` 进行组合, 同时还可以使用 `BETWEEN`比较运算符, 来指定一个范围;

例如:

```sql
SELECT name FROM instructor
WHERE salary BETWEEN 90000 AND 100000
```

---

`from`子句 列出了查询中涉及到的关系;

### 2.5 String Operations 字符串操作

SQL 包含一个用于字符字符串比较的**字符串匹配操作符**, 使用两个特殊字符(**通配符**)来描述:

- `%`: 匹配任意子字符串
- `_` 匹配任意单个字符

可以实现模糊匹配, 放在`where`中, 且必须与`LIKE`连用

例如:

​	找到建筑名字包含`Watson`的部门名字:

```sql
SELECT dept_name
FROM department
WHERE building LIKE '%Watson%';
```

> 当需要搜索实际包含`%`或`_`字符的字符串时, 必须使用`ESCAPE`子句来转义这些特殊字符

例如: `LIKE 'Main\%' escape '\'`

SQL 支持大量的字符串操作:

- concatenation (串联): 使用`||`
  - 例如: `select '教师名=' || name from instructor WHERE ...`
  - 任何值与`NULL`串联后的值都是`NULL`
  
- 大小写转换:
  - 使用函数: `lower()`, `upper()`

- 查找字符串长度, 提取子字符串等; 使用相关函数 `length()`, `substring()`

### 2.7 Duplicates 重复元组

在传统**关系理论**中, 不允许存在重复元组, 但是在实际应用中, 我们需要**允许重复**

某些关系代数运算符存在 **多重集版本**: $\sigma _\theta$, $\Pi _A$, $\times$

对于多重集$r_1, r_2$:

1. $\sigma _\theta(r_1)$: 若有 元组$t_1$的拷贝 $c_1$份, 并且 $t_1$ 满足选择条件, 那么选择结果中就会有 $c_1$份 $t_1$的拷贝
2. $\Pi_A(r_1)$: 对于关系中 $t_1$的每一份拷贝, 结果中就会有一个 $\Pi_A(t_1)$的拷贝
3. $r_1 \times r_2$: 如果 $t_1, t_2$分别有$c_1, c_2$份拷贝, 那么结果中就有 $c_1\times c_2$份对$t_1t_2$的拷贝

SQL 中的选择陈述也同样支持 多重集操作, 为了禁止重复集, 使用`distinct`

## 3. Set Operations 集合操作

在 SQL 中, 使用集合操作: **union, intersect, except**

- 分别对应关系代数中的: $\cup, \cap, -$

每个操作都会**自动消除多重集**

如果要保留所有的多重集, 则需要使用**union all, intersect all, except all**

假设 一个元组 在关系 r s 中分别出现了 m n次, 则:

- `r union all s`中 出现 m+n 次
- `r intersect all s` 中 出现 min(m,n)次
- `r except all s`中 出现 max(0, m-n)次

---

## 4. Aggregate functions 聚合函数

这些函数作用于 关系中某一列的多重集值, 并且返回一个单一值:

- `avg(col)`: 平均值
- `min(col)`: 最小值
- `max(col)`: 最大值
- `sum(col)`: 和
- `count(col)`: 值的数量

**note**: 在 SQL 中使用`GROUP BY`时, 如果选择子句中, 出现在聚合函数之外的属性值, 必须出现在`GROUP BY`中, 否则会报错;

- 为了避免歧义, 保证查询结果的正确性: 分组后每组会被折叠为一行, 其中聚合函数会输出唯一的值, 而如果有不在group by中的属性, 则系统无法得知选择哪个值作为唯一值

**note**: 在`HAVING`子句中出现的属性, 且不在聚合函数中, 那么其必须出现在`GROUP BY`子句中

## SUMMARY

选择子句的形式:

```sql
SELECT <[DISTINCT]c1, c2,...>
FROM <r1, r2,...>
WHERE <cond1>
GROUP BY <c1, c2, ...>
HAVING <cond2>
ORDER BY <c1[DESC][,c2[ASC],...]>
```

执行顺序：`WHERE`, `GROUP BY`, `HAVING`, `SELECT`

HAVING 子句中的谓语是在分组形成之后应用的, 而WHERE 子句中的谓词是在分组形成之前应用的

聚合函数不能直接在 `WHERE`子句中应用

`HAVING`是对分组后的组进行筛选，而不是对分组后每个组内的tuple筛选

## 5. Null Values

元组的一些属性值可能为`NULL`

`NULL`表示一个**未知值** 或者 **不存在的值**

任何涉及到 `NULL` 的计算表达式的值 都是 `NULL`

任何关于 `NULL` 的比较都会返回 `unknown`

`WHERE`子句的 谓词如果是`unknown`, 则会被当做`false`

谓词 `IS NULL`, `IS NOT NULL`可以用作检查属性值是否为`NULL`

- `attribute = null`这种写法是错误的

若谓词 为 `P is unknown`, 如果`P`是unknown的, 则会被评估为`true`, 

聚合函数中忽略`null`值

- 除了`count(*)`

## 7. Views 视图

提供一种机制, 从某些用户的视图中**隐藏特定数据**

视图并不在数据库中以独立的物理文件形式存储数据, 它存储的是一条**预定义的SQL查询语句**

要创建视图, 可以使用以下命令:

```sql
-- 视图的列名直接继承自`select`语句中选择的列名
CREATE VIEW <v_name> AS
	select c1, c2,... from...;
-- 视图的列名显式定义
CREATE VIEW <v_name>(c1, c2,...) AS
	select e1, e2,... from...;
```

使用视图的两个目的:

- 安全性
- 易于使用

删除视图: `DROP VIEW <v_name>`

### 9.4 Update of a View 视图的更新

简单视图通常**可更新**, 而**复杂视图**(涉及多表连接, UNION, 聚合等)通常**无法进行增删改操作**

### 9.5 Transactions 事务

**transaction** 是一组作为单个逻辑单元, 执行查询和数据更新的语句;

事务是隐式启动的, 并通过以下之一终止:

- `commit work`: 使事务的所有更新, 在数据库中永久生效
- `rollback work`: 撤销事务执行的所有更新

两个步骤中, 若一个步骤成功, 而另一个步骤失败, 数据库将处于不一致状态, 因此, 要么都成功, 要么都失败;

**原子性 Atomicity**: 如果事务的任何步骤失败, 事务所做的所有工作都可以通过 rollback work(回滚工作) 撤销

- 在系统故障的情况下, 为完成事务的回滚是自动完成的

**Properties**:

- Atomicity 原子性
- Isolation 隔离性: 并发事务互不干扰
- Consistency 一致性: 数据必须从一个合法状态变到另一个合法状态
- Durability 持久性: 提交后, 修改永远生效

`Join`操作, 接受两个关系, 并返回另一个关系作为结果

**Join type**: 定义了在每个关系中的, 没有和任意一个元组匹配的元组, 最后如何处理(基于join condition)

以上所有连接都是**自然连接**
