1. Overview of Physical Storage Media 物理存储介质概览

数据库的数据是以文件形式存储在物理介质上的(.mdf, .ldf, .ora, .dbf)

存储介质的分类标准:

  • 数据访问速度![[attachments/image-20260427201745506.png]]
  • Cache
  • 主存
  • 闪存 Flash memory
  • 磁性磁盘
  • 光盘
    • 一次写入, 多次读取
    • 多次写入
    • 性能比磁盘慢
  • 磁带存储
  • 单位数据成本
  • 可靠性: 存储介质在存储与访问时的稳定性
  • 易失性存储
  • 非易失性存储

primary storage: 快 volatile

secondary storage(辅助存储器, 联机存储器): non-volatile

  • 也叫做 on-line storage

tertiary storage(三级存储器, 脱机存储器)

  • 也叫做 off-line storage

2. Magnetic Hard Disk Mechanism 磁盘

![[attachments/image-20260427202134404.png]]

  • platter 盘片: 存储数据
  • spindle 主轴: 旋转, 提供盘片安装
  • tracks 磁道: 每个盘片的表面都被分成许多同心圆，这些圆称为磁道。数据就是沿着这些磁道存储的

  • sectors 扇区: 每个磁道都被进一步划分为更小的单元, 作为磁盘上最小可寻址存储单位

  • cylinders 柱面: 位于相同半径的磁道组成一个柱面; 寻址时先定位到柱面, 然后在其上某个盘面找到对应扇区

  • arm assembly 臂总成: 可移动组件, 包含多个臂
  • Read-write head 读写头: 读取或写入磁性数据

2.1. Magnetic Disks 磁盘

读写头:

  • 十分接近盘片表面

扇区: 大多是512 bytes

head-disk assemblies 头盘组合:

  • 每个盘片有两个磁头, 因为盘片两面都可以存储数据

Disk controller 磁盘控制器:

  • 在计算机系统和磁盘驱动器硬件之间进行接口连接
  • 接受读写扇区的高级命令, 磁盘控制器负责将高级命令转化为对硬盘硬件的低级控制信号，指挥臂的移动和磁头的读写操作

  • 数据校验: 为每个扇区计算并附加校验和，以验证数据是否正确读回

  • 确保正常写入: 控制器在写入数据后会立即读取一遍，以确认数据被正确写入

  • 坏扇区重映射:
  • 硬盘在生产过程中可能会有一些物理缺陷，导致某些扇区无法正常读写，这些被称为“坏扇区”。
  • 磁盘控制器会检测到这些坏扇区，并将它们标记出来，然后将数据重定向（映射）到硬盘上预留的备用扇区。这个映射关系会被记录下来，以确保将来对该“逻辑扇区”的访问都能正确地指向备用物理扇区。

2.2. Disk Subsystem

![[attachments/image-20260427231022536.png]]

磁盘接口标准家族:

  • ATA(AT adaptor) 标准家族
  • SCSI
  • 每个标准都有几个变体: 不同的速度与能力
  • RAID: 独立磁盘冗余阵列
  • SAN: 存储区域网络

2.3. Performance Measures of Disks 磁盘性能度量

访问时间(Access time): 从发出读或写请求到数据传输开始所需的时间

  • = 寻道时间 + 旋转等待时间![[attachments/image-20260427232234490.png]]
  • 寻道时间 Seek time: 臂移动以将磁头重新定位到正确磁道所需的时间
  • 旋转等待时间 Rotational latency time: 扇区被访问所需时间
  • 平均延迟 是 最大延迟的一半

数据传输速率 Data-transfer rate: 数据在磁盘与主存之间的传输速度

  • 取决于 旋转速度(盘片旋转越快，每秒经过的扇区越多，传输速率也越高) 和 磁盘接口(带宽决定传输的最大速率)
  • 如果多个磁盘共享同一个控制器，控制器的处理能力也会成为瓶颈

平均故障时间(MTTF, Mean time to failure): 预期的无故障运行的平均时间

2.4. Optimization of Disk-Block Access 磁盘块访问优化

1. Block 块: 来自单个磁道的连续扇区

  • 数据在磁盘和主内存之间以块的形式传输
  • 大小一般在 4 to 16 kb/Block

2. Disk-arm-scheduling algorithms 磁盘臂调度算法:(磁盘臂调度算法) 按顺序处理待定的访问到磁道，从而使磁盘臂移动量最小化

  • 电梯算法 (elevator algorithm): 磁盘臂朝一个方向移动（从外轨道到内轨道或反之），处理该方向上的下一个请求，直到该方向上没有更多请求，然后反向移动并重复

3. File organization 文件组织: 通过组织块以匹配数据访问方式来优化块访问时间

  1. 将相关信息存储在相同或相邻的柱面上

  2. 文件可能会随着时间碎片化 (fragmented)

  3. 例如，如果数据被插入到/从文件中删除。

  4. 或者磁盘上的空闲块是分散的，新创建的文件其块分散在磁盘上。

4. Nonvolatile write buffers 非易失性写缓冲区:

  • 通过将块立即写入非易失性 RAM 缓冲区来加速磁盘写入

5. Log disk 日志盘: 按顺序记录下所有对数据块的更改（更新、插入、删除等）的操作日志

4. File Organization 文件组织
----定长记录和不定长记录组织

Database 以文件集的形式存储

每个文件是记录的序列: 文件是按照一定的顺序存储数据的，而这些数据是以“记录”为单位组织的

记录是字段的序列

  • 定长记录 Fixed-length records
  • 不定长记录 Variable-length records

4.1 定长记录

advantages:

  • 对于 record i 的存储, 从byte $n*(i-1)$开始, 其中n是每个record的大小![[attachments/image-20260428115517443.png]]
  • 记录访问很快, 但是record 可能会跨越 block
  • 修改: 不允许 record 跨越 block

删除 record i 可选方法:

  • method 1: 将 records i+1, ..., n 移动到 i, ..., n-1
  • method 2: 将 record n 移动到 i
  • method 3: 不移动 records, 但将所有空记录连接到一个空闲列表(free list)

free lists:

![[attachments/image-20260428120041025.png]]

  • 在文件头存储第一个被删除记录的地址

  • 用第一个record存储第二个被删除记录的地址, 等等

  • 可以将这些存储的地址视为指针, 因为它们"指向"记录的位置
  • 优点: 更节省空间的表示方法：重用空间来存储空闲记录的常规属性，以存储指针。（在使用的记录中不存储指针）

插入: 先找到header中记录着的第一个空闲record, 写入数据后调整header使其指向下一个空闲record

4.2 不定长记录

不定长记录如何产生:

  • 记录类型允许一个或多个字段的可变长度
  • 在一个文件中存储多种记录类型
  • 记录类型允许重复字段

属性按照顺序存储

可变长度属性由固定大小( 偏移量, 长度 )表示, 实际数据存储在所有固定长度属性之后

null 值由 null-value 位图表示

分槽的页结构![[attachments/image-20260508133302569.png]]![[attachments/image-20260508133511723.png]]

  • 槽页(slotted page) 头包含:
  • 记录的数量(即槽的数量)
  • 指示页内可用空间的结束位置

  • 每个记录在页内的具体位置(偏移量) 和 大小

  • 记录的页内移动:

  • 记录可以在页面内移动，以使它们保持连续且之间没有空隙；头部中的条目必须更新。

  • 间接指针: 索引中的指针不直接指向记录在页中的实际位置, 而是指向页头中的槽 rid = <slot# pid>

![[attachments/image-20260508134436124.png]]

5. Organization of Records in Files 文件中记录的组织 ---- 关于存放次序

  • 堆文件(Heap file): 记录可以放置在文件中任何有空间的地方
  • 顺序文件(Sequential file): 根据每条记录的搜索键值, 按顺序存储

  • 散列文件(Hashing file): 在每条记录的某个属性上计算哈希函数；结果指定了记录应放置在文件的哪个块中

  • 聚集文件组织 (Clustering file organization): 几个不同关系的记录可以存储在同一个文件中

  • 动机：将不同关系中的相关记录存储在同一个块上，以最小化 I/O

1. Heap File Organization

记录可以放置在任意free space

记录通常不移动, 一次分配

重要的是如何高效找到其中的 free space: Free-space map

  • 一个数组, 文件的每个块在数组中都有一个对应项。每个项占几位到一个字节，记录该块的空闲比例![[attachments/image-20260508142529607.png]]

  • 当文件非常大时, 扫描整个一级映射表也会变慢, 可以有二级free-space map:

  • 二级映射中的每一个项代表一级映射中一组项的最大值![[attachments/image-20260508142640108.png]]

  • 空闲空间图定期写入磁盘，允许部分条目拥有错误（旧）值（会被检测并修复）

2. Sequential File Organization 顺序文件组织

适合需要顺序处理文件的应用

文件中的记录是根据搜索键(Search-key) 的大小顺序排列的

![[attachments/image-20260511104021979.png]]

  • Deletion: 使用指针链(Pointer chains)

  • 在逻辑上进行删除

  • Insertion: 插入的新纪录需要保持逻辑上的排序

  • 定位位置

  • 有空闲空间: 直接插入并且更新指针

  • 无空闲空间, 插入到溢出块(Overflow block) 中, 更新指针链![[attachments/image-20260511104507181.png]]

  • 需要定期对文件重新排序: 随着插入的记录越来越多，大量的记录会被存放在溢出块中，且指针链会变得非常乱（在磁盘的不同位置跳来跳去）。这会导致原本很快的顺序扫描变得非常慢

    • 解决方法：定期对文件进行重组（Reorganize）, 系统会找个时间（如深夜），把所有记录按顺序重新读出来，然后整齐地、物理连续地写回主存储区，清空溢出块，恢复完美的物理顺序。

3. Clustering File Organization 聚簇文件组织

传统做法: 通常数据库将每个关系（表）存储在一个独立的文件中

聚簇文件: 将多个相关的表（例如“部门”表和“教师”表）混合存储在同一个文件中

存储逻辑: 将那些在连接查询（Join）中经常一起出现、具有相同属性值的记录，在物理磁盘上存放在一起

![[attachments/image-20260511104914086.png]]

优点:

  • 极大地提高连接查询（Join）效率：当你执行 department ⋈ instructor（查询部门及其对应的教师）时，数据库磁头只需在磁盘的一个连续区域读取，不需要在两个不同的文件之间来回跳跃，大幅减少了磁盘 I/O 开销。
  • 适用于父子关系：例如“一个客户及其所有账户信息”，这种经常需要一起调用的数据非常适合聚簇存放

缺点:

  • 单表查询性能下降：如果你只想查询“所有部门的名称”，系统在扫描文件时，必须被迫跳过夹杂在其中的大量教师记录。这比扫描一个纯粹的部门表要慢得多
  • 记录长度不固定（Variable size records）：由于每个部门下的教师数量不等，导致物理存储块中的记录长度不一，增加了空间管理的复杂性

6. Data Dictionary Storage 数据的字典存储

数据字典，也常被称为系统目录 (System Catalog)，是数据库管理系统（DBMS）存放元数据（Metadata） 的地方。所谓元数据，简单来说就是“ 关于数据的数据”

关键内容:

  1. 关于关系（表）的信息 (Information about relations)
  2. 关系名：表的名称是什么。
  3. 属性的名字和类型：每一列叫什么名字，存储的是整数、字符串还是日期等。
  4. 视图的名称和定义：虚拟表的定义逻辑。

  5. 完整性约束：例如主键（Primary Key）、外键（Foreign Key）以及哪些列不能为空等规则。

  6. 用户与账户信息 (User and accounting information), 包括密码

  7. 统计与描述性数据 (Statistical and descriptive data)

  8. 每个关系中的元组（行）数量：了解表的大小，帮助数据库决定是用索引查找还是全表扫描更快

  9. 物理文件组织信息 (Physical file organization information) :描述数据在磁盘上是怎么放的：

  10. 存储方式：是顺序存储、哈希存储还是堆文件组织

  11. 物理位置：在操作系统中的文件名，或者在磁盘上的具体块地址

  12. 关于索引的信息 (Information about indices)

目录结构 的两种选择:

  • 专门的数据结构
  • 一组关系表: 直接用数据库现有表处理功能来存储元数据

通常选择后者

![[attachments/image-20260511190041107.png]]

7. Data Buffer 数据缓冲

磁盘的访问速度比内存慢了约 100万倍（1毫秒 = 1,000,000纳秒）。如果数据库每次读写都直接找磁盘，CPU大部分时间都会处于无所事事的等待状态

缓冲区: 指内存（RAM）中专门划出来的一块区域，用于存放从磁盘读入的数据块副本

目标: 尽量减少磁盘与内存之间的块传输次数

缓冲区管理器:

  1. 分配空间：在内存中为读入的数据块分配位置

  2. 命中处理：当程序请求某个块时，先看缓冲区里有没有。如果有（称为缓存命中），直接给CPU，速度极快

  3. 替换策略：当缓冲区满了，又有新的块要进来时，决定把哪个旧的块“踢出”内存，写回磁盘

![[attachments/image-20260511191442791.png]]

映射表(): 系统维护着一张表，记录哪个内存帧（Frame #）里存着哪一个数据页（Page ID）

替换策略:

  • LRU 最近最少使用 : 在重复扫描模式下会变得非常糟糕![[attachments/image-20260511192553071.png]]

  • MRU 最近最多使用

  • 使用脏块写回

  • 当dirty bit = 1则必须写回, 若dirty bit = 0, 直接覆盖即可

  • Pinned Block 钉住的块: 当一个事务（程序）正在操作某个内存块时，它会把这个块“钉住（Pin）”。被钉住的块绝对不允许被写回磁盘或被其他数据替换。

  • Pin count: 记录一个数据块正在被多少个事务使用, 只有当pin count = 0时, 才允许被替换
  • Toss-immediate: 用后立即丢弃

8. Column-Oriented Storage 列式存储

将一个属性的所有值存放在一起![[attachments/image-20260511193108855.png]]

优点:

  • 减少 IO 开销：如果查询只访问部分属性（列），则只需从磁盘读取对应的列，无需读取整行数据。
  • 提高 CPU 缓存性能：由于同一列的数据连续存储，具有更高的数据局部性，能更有效地利用 CPU 缓存，减少缓存失效。
  • 提高压缩效率：同一列的数据类型相同且相似度高，压缩效果远好于行式存储，节省空间。
  • 支持现代 CPU 架构的向量化处理 (Vector processing)：现代 CPU 可以利用 SIMD 指令集一次处理多个数据值（如同时对一列数值求和），性能极高。

缺点:

  • 元组重构成本高：如果需要查询整行记录（SELECT *），数据库必须从各个不同的列文件中把碎片拼凑起来，这个过程（Tuple Reconstruction）非常耗时。
  • 删除和更新成本高：修改或删除一行数据意味着需要同时操作多个列文件，维护成本极高。
  • 解压缩成本：虽然节省了空间，但读取数据时需要消耗额外的 CPU 资源进行解压缩。
