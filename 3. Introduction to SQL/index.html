    Chapter 3: Introduction to SQL

    Introduction to SQL

    SQL: Structured Query Language, 结构化查询语言

    SQL 包含几个部分:

    • DDL (Data-definition Language) 数据定义
    • Create table, alter table, drop table
    • create index, drop index
    • create view, drop view
    • create trigger, drop trigger
    • DML (Data-manipulation Language) 数据操纵
    • select...from
    • insert, delete, update
    • DCL (Data-control Language) 数据控制
    • grant, revoke

    1. Data Definition Language (DDL)

    DDL 的主要功能:

    • 定义每个关系的关系模式(schema)
    • 指定每个属性的域值(domain)
    • 完整性约束
    • 定义每个关系在磁盘上的物理存储结构
    • 定义每个关系维护的索引(indices)
    • 定义对关系的视图(view)

    1.1 Domain Types in SQL

    • char(n) : 固定长度字符字符串, 用户指定长度为n
    • varchar(n): 可变长度的字符字符串, 用户指定最大长度为n
    • int: 整数,(机器依赖的整数有限子集)
    • smallint: 小整数(整数域的一个机器依赖的子集)
    • numeric(p,d): 定点数, 用户指定精度为p位数字, 其中小数点后有d位
    • real, double precision: 浮点数和双精度浮点数, 其精度取决于机器
    • float(n): 浮点数, 用户指定至少n位有效数字的精度
    • 所有域类型都允许null值; 将某个属性声明为not null可以禁止该属性取null值
    • date: 日期类型, 包含四位数的年份, 月份和日期
    • 例如: date '2007-2-27'
    • time: 表示一天中的时间, 包括小时, 分钟和秒
    • 例如: time '08:15:30'
    • timestamp: 日期 + 时间 的组合, 即完整的时间戳
    • 例如: timestamp '2007-2-27 08:15:30.75'

    在 SQL Server 2000 中, 日期和时间的类型统称为"datetime"

    SQL 中有许多函数, 用于处理各种数据类型 以及 类型转化

    1.2 Create Table Construct 创建表语句

    SQL 中的关系 使用CREATE TABLE命令定义:

    CREATE TABLE r(A1 D1, 
               A2 D2, 
               ..., 
               An Dn, 
               (integrity constraint1),
               ...,
               (integrity constraintk))
    • r 是关系名
    • 每个 Ai 是属性名
    • Di 是属性 Ai 的域的数据类型
    Integrity Constraints in Create Table 完整性约束
    • not null
    • primary key (A1, ..., An)
    • check(P), 其中 P 是一个谓词(条件表达式)

    从 SQL_92 开始, 对属性声明 primary key会自动确保 not null

    在 SQL_89 中, 则需要显式写出 not null

    使用两种方法指定 ID 为 primary key

    1.3 Drop and Alter Table 删除 和 修改 表

    Drop Table:

    DROP TABLE 会从数据库中删除关于被删除关系的所有信息

    • DROP TABLE r;

    Alter Table:

    1. 修改表用于向已经存在的关系中添加(add):

    2. ALTER TABLE r ADD A D;

    3. ALTER TABLE r ADD (A1 D1,..., An Dn);

    ​ 其中 A 是属性名字, D是A的域

    • 所有元组的新的属性的值都会被赋值为null

    • 修改表也可以删除(drop)关系的一些属性:

    • ALTER TABLE r DROP A

    但是很多数据库不支持对属性的删除

    1. 修改表也可以修改(modify)关系的属性:

    2. ALTER TABLE instructor MODIFY (ID char(10), salary not null)

    1.4 Create Index 创建索引

    CREATE INDEX <i-name> ON <table-name>(<attribute-list);

    • 创建一个索引，指定索引名称、表名和要建立索引的属性列表

    例如:create index ins_index on instructor(ID)

    ​ create index ins_ID_name_index on instructor(ID, name)

    CREATE UNIQUE INDEX <i-name> ON <table-name>(attribute-list);

    • 创建一个唯一索引，确保所选属性的值是唯一的(即指定 candidate key)

    例如:create unique index uni_stu_index on student(ID)

    DROP INDEX <i-name>

    • 删除索引

    2. Basic Structure of Select

    一个典型的 SQL 查询为如下形式

    SELECT A1, A2, ... An
FROM r1, r2, ..., rm
WHERE P

    其对应的关系代数为: $\Pi _{A_1, A_2, ..., A_n}(\sigma _P(r_1 \times ... \times r_m))$

    这个 SQL 查询的结果是一个关系

    2.1 The select Clause (select子句)

    select子句对应着 关系代数中的 投影$\Pi$

    note: SQL 中不允许字符-出现在名字中;

    ​ 例如: 使用dept_name; 而不是dept-name

    note: SQL 名称不区分大小写

    SQL 允许关系中以及查询结果中存在重复项;

    • 若要强制消除重复项, 可以在SELECT后添加关键字distinct

    • 相反的关键字all允许保留重复项

    默认情况下, 允许重复项, 即ALL是默认选项

    SELECT 子句中, *代表所有属性;

    • SELECT * FROM instructor;

    SELECT 子句可以包含算数表达式, 涉及运算符+,-,*,/, 并作用于常量 或者 元组的性质上(广义投影)

    ​ 例如:SELECT ID, name, salary * 1.05 FROM instructor;

    2.2 The Where Clause (where子句)

    WHERE子句 用于指定结果必须满足的条件, 它对应于关系代数中的选择谓词 selection predicate $\sigma$

    WHERE 子句中, 比较结果可以用逻辑连接词 AND OR NOT 进行组合, 同时还可以使用 BETWEEN比较运算符, 来指定一个范围;

    例如:

    SELECT name FROM instructor
WHERE salary BETWEEN 90000 AND 100000

    2.3 The From Clause (from 子句)

    from子句 列出了查询中涉及到的关系;

    • 如果指定了不止一个关系, 则对应于关系代数中的 笛卡儿积 $\times$

    例如:

    ​ 对应的 SQL 查询语句:

    SELECT name, course_id
FROM instructor, teaches
WHERE instructor.ID = teaches.ID and dept_name = 'Biology';

    2.4 The Rename Operation 重命名操作

    a. Column rename 属性重命名

    as 是可选的

    在 SQL server 中, 允许使用格式: new-name = column 表达式

    例如:

    SELECT name as instructor_name, course_id
FROM instructor, teaches
WHERE instructor.ID = teaches.ID and dept_name = 'Biology';

    其中 name as instructor_name 在 SQL server 中等价于name = instructor_name

    b. Relation rename 关系重命名 - Tuple Variables 元组变量

    Tuple variables 被定义在from子句中, 通过使用as子句

    必须为临时表赋一个变量名

    为表起别名, 是为了引用更简洁, 清晰

    2.5 String Operations 字符串操作

    SQL 包含一个用于字符字符串比较的字符串匹配操作符, 使用两个特殊字符(通配符)来描述:

    • %: 匹配任意子字符串
    • _ 匹配任意单个字符

    可以实现模糊匹配, 放在where中, 且必须与LIKE连用

    例如:

    ​ 找到建筑名字包含Watson的部门名字:

    SELECT dept_name
FROM department
WHERE building LIKE '%Watson%';

    当需要搜索实际包含%或_字符的字符串时, 必须使用ESCAPE子句来转义这些特殊字符

    例如: LIKE 'Main\%' escape '\'

    SQL 支持大量的字符串操作:

    • concatenation (串联): 使用||
    • 例如: select '教师名=' || name from instructor WHERE ...

    • 任何值与NULL串联后的值都是NULL

    • 大小写转换:

    • 使用函数: lower(), upper()

    • 查找字符串长度, 提取子字符串等; 使用相关函数 length(), substring()

    2.6 Ordering the Display of Tuples 对元组显示结果进行排序

    desc 指明 降序

    asc 指明 升序

    • 默认升序

    例如:

    SELECT *
FROM instructor
ORDER BY salary desc, name asc;

    2.7 Duplicates 重复元组

    在传统关系理论中, 不允许存在重复元组, 但是在实际应用中, 我们需要允许重复

    某些关系代数运算符存在 多重集版本: $\sigma _\theta$, $\Pi _A$, $\times$

    对于多重集$r_1, r_2$:

    1. $\sigma _\theta(r_1)$: 若有 元组$t_1$的拷贝 $c_1$份, 并且 $t_1$ 满足选择条件, 那么选择结果中就会有 $c_1$份 $t_1$的拷贝
    2. $\Pi_A(r_1)$: 对于关系中 $t_1$的每一份拷贝, 结果中就会有一个 $\Pi_A(t_1)$的拷贝
    3. $r_1 \times r_2$: 如果 $t_1, t_2$分别有$c_1, c_2$份拷贝, 那么结果中就有 $c_1\times c_2$份对$t_1t_2$的拷贝

    SQL 中的选择陈述也同样支持 多重集操作, 为了禁止重复集, 使用distinct

    3. Set Operations 集合操作

    在 SQL 中, 使用集合操作: union, intersect, except

    • 分别对应关系代数中的: $\cup, \cap, -$

    每个操作都会自动消除多重集

    如果要保留所有的多重集, 则需要使用union all, intersect all, except all

    假设 一个元组 在关系 r s 中分别出现了 m n次, 则:

    • r union all s中 出现 m+n 次
    • r intersect all s 中 出现 min(m,n)次
    • r except all s中 出现 max(0, m-n)次

    4. Aggregate functions 聚合函数

    这些函数作用于 关系中某一列的多重集值, 并且返回一个单一值:

    • avg(col): 平均值
    • min(col): 最小值
    • max(col): 最大值
    • sum(col): 和
    • count(col): 值的数量

    note: 在 SQL 中使用GROUP BY时, 如果选择子句中, 出现在聚合函数之外的属性值, 必须出现在GROUP BY中, 否则会报错;

    • 为了避免歧义, 保证查询结果的正确性: 分组后每组会被折叠为一行, 其中聚合函数会输出唯一的值, 而如果有不在group by中的属性, 则系统无法得知选择哪个值作为唯一值

    note: 在HAVING子句中出现的属性, 且不在聚合函数中, 那么其必须出现在GROUP BY子句中

    SUMMARY

    选择子句的形式:

    SELECT <[DISTINCT]c1, c2,...>
FROM <r1, r2,...>
WHERE <cond1>
GROUP BY <c1, c2, ...>
HAVING <cond2>
ORDER BY <c1[DESC][,c2[ASC],...]>

    执行顺序：WHERE, GROUP BY, HAVING, SELECT

    HAVING 子句中的谓语是在分组形成之后应用的, 而WHERE 子句中的谓词是在分组形成之前应用的

    聚合函数不能直接在 WHERE子句中应用

    HAVING是对分组后的组进行筛选，而不是对分组后每个组内的tuple筛选

    5. Null Values

    元组的一些属性值可能为NULL

    NULL表示一个未知值 或者 不存在的值

    任何涉及到 NULL 的计算表达式的值 都是 NULL

    任何关于 NULL 的比较都会返回 unknown

    WHERE子句的 谓词如果是unknown, 则会被当做false

    谓词 IS NULL, IS NOT NULL可以用作检查属性值是否为NULL

    • attribute = null这种写法是错误的

    若谓词 为 P is unknown, 如果P是unknown的, 则会被评估为true,

    聚合函数中忽略null值

    • 除了count(*)

    6. Nested Subqueries 嵌套子查询

    子查询是SELECT FROM WHERE表达式中嵌套另一个查询

    子查询一个常见用途是执行 集合成员的比较测试

    6.1 Set Comparison

    Some 子句:

    C <comp> some r 即 关系r中存在元组t, 使得c <comp> t, 其中<comp> 可以是$<,\le, >, =, \neq$

    all 子句

    C <comp> all r 即关系r中所有元组t, 使得 c <comp> t, 其中<comp> 可以是$<,\le, >, =, \neq$

    6.2 Test for Empty Relations 测试空关系

    exists r 等价于 r 不为空集

    not exists r 等价于 r 为空集

    若 某一元组 t 能够使得子查询获得一个空集, 则被选择;

    6.3 Test for Absence of Duplicate Tuples 测试是否存在重复元组

    unique 结构 用于测试子查询的结果中, 是否包含任何重复的元组

    not unique 结构 用于表示子查询的结果中, 至少包含一个重复元组

    7. Views 视图

    提供一种机制, 从某些用户的视图中隐藏特定数据

    视图并不在数据库中以独立的物理文件形式存储数据, 它存储的是一条预定义的SQL查询语句

    要创建视图, 可以使用以下命令:

    -- 视图的列名直接继承自`select`语句中选择的列名
CREATE VIEW <v_name> AS
    select c1, c2,... from...;
-- 视图的列名显式定义
CREATE VIEW <v_name>(c1, c2,...) AS
    select e1, e2,... from...;

    使用视图的两个目的:

    • 安全性
    • 易于使用

    删除视图: DROP VIEW <v_name>

    sql DELETE FROM <talbe/view> WHERE <condition>

    INSERT INTO <table/view>[(c1,c2,...)]

    但是若未指定插入值但是该属性不允许为null:

    • 若有默认值, 则赋值为默认值
    • 若无默认值, 则报错

    简单视图通常可更新, 而复杂视图(涉及多表连接, UNION, 聚合等)通常无法进行增删改操作

    View 是虚表, 对其进行的所有操作都会被转化为对基表的操作

    9.5 Transactions 事务

    transaction 是一组作为单个逻辑单元, 执行查询和数据更新的语句;

    事务是隐式启动的, 并通过以下之一终止:

    • commit work: 使事务的所有更新, 在数据库中永久生效
    • rollback work: 撤销事务执行的所有更新

    两个步骤中, 若一个步骤成功, 而另一个步骤失败, 数据库将处于不一致状态, 因此, 要么都成功, 要么都失败;

    原子性 Atomicity: 如果事务的任何步骤失败, 事务所做的所有工作都可以通过 rollback work(回滚工作) 撤销

    • 在系统故障的情况下, 为完成事务的回滚是自动完成的

    Properties:

    • Atomicity 原子性
    • Isolation 隔离性: 并发事务互不干扰
    • Consistency 一致性: 数据必须从一个合法状态变到另一个合法状态
    • Durability 持久性: 提交后, 修改永远生效

    10. Joined Relations 关系的连接

    Join操作, 接受两个关系, 并返回另一个关系作为结果

    Join condition: 定义了两个关系中的哪两个元组匹配, 并且哪些属性会被呈现到连接的结果中

    Join type: 定义了在每个关系中的, 没有和任意一个元组匹配的元组, 最后如何处理(基于join condition)

    以上所有连接都是自然连接

    • 自动将同名列作为连接条件
    • 自动去重: 最终结果中, 作为连接条件的同名列只出现一次

    非自然连接:

    • 明确指定连接条件
    • 结果集会保留所有列
    • On子句, 指定任意连接条件
    • USING: 结果中指定的列也会只出现一次

    主流商用数据库中外连接的表示:

    • SQL Server

    • *=: 左外连接, 等价于LEFT JOIN

    • =*: 右外连接, 等价于RIGHT JOIN

    • ORACLE

    • 左连接: loan.loan_number = borrower.loan_number(+)
    • 右连接: loan.loan_number(+) = borrower.loan_number

    相当于在 (+) 一侧附加一特殊空行, 与另一个表中的连接属性匹配
